# 性能优化方案分析

## 📊 当前性能瓶颈

### 实测数据

**Hand vs Hand (AKs vs QQ):**
```
迭代次数    耗时      精度 (理论46.3%)
100次      30ms     37.5% (误差9%)
500次     149ms     47.1% (误差0.8%)
1000次    302ms     45.9% (误差0.4%)
5000次   1534ms     45.9% (误差0.4%)
10000次  2941ms     46.4% (误差0.1%)
```

**Hand vs Range (AKs vs {QQ+,AK} 18 combos):**
```
迭代次数/combo    总耗时
1000次           6.3秒   ❌ 太慢
500次            3.1秒   ❌ 太慢
200次            1.2秒   ⚠️ 勉强可用
```

### 核心问题

1. **默认迭代次数太高** (10000次)
2. **Range计算需要遍历所有combos**
3. **没有缓存机制**
4. **纯Python实现，无并行**

## 🎯 优化方案

### 方案1: 降低迭代次数 ⭐⭐⭐⭐⭐

**精度影响:** ⚠️ 轻微 (可控)
**性能提升:** 🚀 10倍
**实现难度:** ✅ 极简单

#### 具体改动

```python
# 当前默认
EquityCalculator(iterations=10000)  # 太慢

# 优化后
EquityCalculator(iterations=1000)   # 精度0.5%，速度快10倍
```

#### 分场景优化

| 场景 | 建议迭代次数 | 耗时 | 精度误差 |
|------|------------|------|---------|
| Hand vs Hand (翻前) | 500-1000 | 150-300ms | ±0.5% |
| Hand vs Hand (翻后) | 300-500 | 100-200ms | ±1% |
| Hand vs Range | 200-300 | 按combo数 | ±1% |
| Range vs Range | 100-200 | 按采样数 | ±2% |

**推荐配置:**
- 翻前精确计算: 1000次
- 翻后快速决策: 300次
- 大范围估算: 200次

### 方案2: 智能采样 (Range vs Range) ⭐⭐⭐⭐

**精度影响:** ⚠️ 中等 (1-2%)
**性能提升:** 🚀 5-20倍
**实现难度:** ⚙️ 简单

#### 核心思路

Range vs Range不需要计算**所有**组合，采样即可：

```python
# 当前: 计算所有组合
hero_range: 100 combos
villain_range: 200 combos
总计算: 100 × 200 = 20,000 对抗  ❌ 太慢

# 优化: 采样代表性组合
sample_size: 50-100
总计算: 50-100 对抗  ✅ 快20倍
```

**已实现:** `calculate_range_vs_range()` 已支持 `sample_size` 参数

### 方案3: 翻前查表法 ⭐⭐⭐⭐⭐

**精度影响:** ✅ 无 (预计算精确值)
**性能提升:** 🚀 1000倍+
**实现难度:** ⚙️⚙️ 中等

#### 原理

翻前equity是固定的，可以预计算：

```python
# 示例: AKs vs 各种对手
preflop_equity_table = {
    ('AsKs', 'QhQd'): 0.463,  # 预计算
    ('AsKs', 'AhKh'): 0.500,  # 平局
    # ... 1326 × 1326 = 1,755,876 种组合
}

# 使用时直接查表，0ms
equity = preflop_equity_table.get((hero, villain))
```

#### 实现策略

**完整版** (不推荐):
- 预计算所有1.7M组合 → 几GB数据

**实用版** (推荐):
- 只计算关键对抗 (Top 5000种)
- 其他用简化公式估算
- 数据量: ~100KB

### 方案4: 上下文感知精度 ⭐⭐⭐⭐

**精度影响:** ⚠️ 场景化 (合理)
**性能提升:** 🚀 2-5倍
**实现难度:** ⚙️ 简单

#### 核心思路

**不是所有决策都需要高精度:**

| 场景 | 需要精度 | 建议迭代 |
|------|---------|---------|
| All-in决策 (深筹码) | 高 (0.5%) | 1000次 |
| 小底池翻后决策 | 中 (1-2%) | 300次 |
| 明显弃牌 (equity<30%) | 低 (5%) | 100次 |
| 明显跟注 (equity>60%) | 低 (5%) | 100次 |

**动态调整:**
```python
def get_iterations(pot_size, effective_stack, equity_estimate):
    # SPR很高 → 精确计算
    if effective_stack / pot_size > 10:
        return 1000

    # 小底池 → 快速估算
    if pot_size < 5:  # 5BB
        return 200

    # 边缘决策 → 精确计算
    if 0.4 < equity_estimate < 0.6:
        return 800

    # 明显决策 → 粗略估算
    return 300
```

### 方案5: 缓存机制 ⭐⭐⭐

**精度影响:** ✅ 无
**性能提升:** 🚀 10倍+ (重复查询)
**实现难度:** ⚙️⚙️ 中等

#### 实现

```python
from functools import lru_cache

@lru_cache(maxsize=1000)
def cached_equity(hero_str, villain_str, board_str, iterations):
    """缓存equity计算结果"""
    hero = Hand.from_str(hero_str)
    villain = Hand.from_str(villain_str)
    board = Board.from_str(board_str)

    calc = EquityCalculator(iterations)
    return calc.calculate_equity(hero, villain, board)
```

**适用场景:**
- 对手范围固定 (同一手牌多次查询)
- Advisor生成多个sizing option
- 测试和benchmark

## ❓ 精度影响评估

### 1000次 vs 10000次 对比

**理论分析:**
- 标准差: σ ∝ 1/√n
- 10000次: σ ≈ 0.5%
- 1000次: σ ≈ 1.6%
- 500次: σ ≈ 2.2%

**实战影响:**
```
场景: Hero拿AKs, 底池100, 对手推All-in 50

10000次: Equity = 46.4% → EV = 46.4*150 - 53.6*50 = +42.8
1000次:  Equity = 45.9% → EV = 45.9*150 - 54.1*50 = +41.8
差异: 1BB (1%)

结论: 决策一致 (都是Call)，EV差异可忽略
```

**什么时候影响决策:**
- 非常边缘的情况 (equity 49.5% vs 50.5%)
- 实战中极少出现 (<1%)
- 可以用"增加迭代"来处理边缘case
